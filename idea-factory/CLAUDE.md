# Idea Factory: rules for every agent and session in this repo

Owner: Nick (solo builder, Royal Oak, MI). Nick directs; agents do the work. Explain decisions in plain language.

## Hard rules
1. **Validate first; the G1 sample is a working prototype, not a launch.** Lanes go G0 -> G1 -> G2 -> G3 only. Nick's decision of 2026-10-25: G1 must produce the product as a customer would actually open it, an interactive web app on live data (map, visuals, phone layout, daily refresh) built with `core.webapp`, saved in `lanes/<slug>/app/` and reviewable as a published page. Still forbidden before GO and Nick's approval: accounts, payments, customer databases, email delivery, app-store publishing, paid hosting. A spreadsheet or PDF alone is not a G1 pass any more. After GO, write a one-page build plan (launch work only) and stop.
2. **Never send, post, buy or sign up.** Draft it and put it in the lane's `needs_nick.md`. Free tiers and free API keys only. Anything that costs money is a question for Nick.
3. **License first.** Register every data source in `core/sources.json` (shared) or `lanes/<slug>/sources.json` (lane-specific) with license, terms URL and update frequency before fetching through it. `commercial_ok=false` means KILL or flag the lane.
4. **No people data.** Public business, infrastructure, weather and government data only. Never track, identify or profile individuals. Permits: address, permit details, contractor of record only; no homeowner enrichment.
5. **Lanes write only inside `lanes/<slug>/`.** Everything in `/ops` is regenerated by `python -m core.board`. Never hand-edit ops/STATUS.md, NEEDS_NICK.md, SCORECARD.md or DATA_SOURCES.md.
6. **Reuse core.** `core.fetch.Fetcher` for every HTTP call (cache, retries, budgets, usage log), `core.samples` for CSV/HTML/PDF, `core.outreach` for G2 drafts, `core.mailmerge` to turn a pack into Nick's send sheet and ready-to-send drafts (`python -m core.mailmerge <slug> [--eml DIR]`; outreach emails are written in plain first person, see the tone rules in `core/outreach.py`), `core.scoring.Score` for G3, `core.lane` for state. If core is missing something a lane needs, add it to core (small, general), not to the lane.
7. Standard library only on the Python side. Nothing to pip install. Front-end prototypes are static HTML/CSS/JS in `lanes/<slug>/app/`, scaffolded by `core.webapp` (shared tokens, both themes, manifest, service worker, icons, data folder). Browser libraries only from cdnjs.cloudflare.com pinned to an exact version (Leaflet 1.9.4 for maps); map boundaries come from `core.geo` (Census TIGERweb, public domain) as inlined GeoJSON so the map renders with no tile server; raster tiles (OpenStreetMap, NOAA radar) are optional layers the page turns on only when it can load them. No build step, no bundler, no npm in lanes.
8. **`ops/FROM_NICK.md` is Nick's voice; read it first, never edit it.** Nick finishes Needs-Nick items in his Task Desk app, which appends a dated entry (lane, task, his notes, pasted replies/volumes/decisions) to that file. It is append-only and belongs to the app. `scripts/tick.py` runs `core.from_nick` first: it ticks the matching box in the lane's `needs_nick.md` (or `ops/needs_nick_global.md`), files pasted results (`outreach/replies.md`, `data/keyword_volumes.csv`, raw copy in `lanes/<slug>/from_nick/`), writes a LANE.md log line naming the entry, records it in `ops/from_nick_ledger.jsonl`, and sets the lane back to `active` when no open Nick items remain. The tick agent then continues each such lane from Nick's notes (re-score, kill, merge, or move on) and says in LANE.md which FROM_NICK entry it acted on. A SKIPPED entry means Nick chose not to do it: treat the demand evidence as absent, do not re-ask.

## Lane workflow (what a lane agent does)
```
python -m core.lane <slug> start G0 "what you are checking"
# ... work: fetch via core.fetch, write findings into lanes/<slug>/LANE.md under the gate heading
python -m core.lane <slug> finish G0 pass|fail "one-line evidence"
```
- G0 Data check: endpoint works (real request), license allows commercial use, update frequency fits the product. Fail = KILL with reason.
- G1 Prototype: the product as a customer would open it, from real current data. `python -m core.webapp scaffold <slug> --title ...` gives the shell in `lanes/<slug>/app/`; the lane writes `index.html`, `app.js` and has its `refresh.py` write `app/data/*.json` (so the daily tick keeps it live). Maps: Leaflet 1.9.4 from cdnjs over inlined GeoJSON from `core/web/geo/` (state, 83 counties, 992 ZCTAs); raster layers only behind `Factory.canLoadImage`. Must work on a phone and in both themes. `python -m core.webapp check <slug>` must print OK before G1 is marked passed. Keep writing the CSV/PDF sample too; it is the email attachment for outreach.
- G2 Demand test: revenue lanes -> 10-20 target businesses (public listings) + outreach emails + 3-question survey via `core.outreach`. Traffic lanes -> ~40 search queries for Keyword Planner with exact steps, plus competitor audit of top 5 results for 10 queries. Then `python -m core.lane <slug> status waiting_nick --blocker "..."` and stop; the lane parks and frees its slot.
- G3 Decision: `python -m core.scoring <slug> --demand N --repeat-use N --competition N --license N --build-effort N --why-demand "..." ... [--merge-with slug ...] [--provisional]`. Use `--provisional` whenever the demand score is a guess (no replies or search volumes yet): it records the score but never lets the decision be GO. Drop the flag only after real demand evidence is in. Name overlapping lanes with `--merge-with`. Gate timing for G2/G3 is stamped automatically by `core.outreach` and `core.scoring`.
- Keep `lane.json` honest: it drives the portfolio board. Keep a short log at the bottom of LANE.md.
- Record how long each gate took and what blocked you; the system report needs it.

## Layout
- `core/` shared code. `lanes/<slug>/` one folder per idea. `ops/` roll-ups and operating files. `scripts/` tick and digest.
- `ops/queue.json` is the ordered idea backlog; `ops/INBOX.md` is where Nick pastes new ideas.
